## Question, data, timing and leakage rule

Predict **whether a credit-card yellow taxi trip records a tip greater than 20% of its fare** using *pickup-time* inputs only (pickup borough, hour/day/month, vendor and passengers). Cash tips are not observed in this public record: `payment_type=1` is an outcome-observation restriction, **not** a feature. The TLC dictionary calls `RatecodeID` the **final code at the end of the trip**, so it too is excluded. `fare_amount`, `tip_amount`, `total_amount`, `trip_distance`, dropoff time/zone and payment type are excluded from the feature vector; realised distance is only used for retrospective Task4 charts. The model applies to trips known to use a card, not indiscriminately at pickup before payment method is known. We do not claim a booking-time estimate for unknown future trip length. Month is represented with sine/cosine rather than a StringIndexer trained on Jan–Sep (which would label November/December as unseen). Temporal periods are Jan–Sep 2019 for training/CV, October for operating-threshold selection, Nov–Dec for untouched final evaluation. CV folds are *calendar-day grouped*, not truly forward-chaining; explain this limitation.

The NYC TLC [official data page](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page) documents the Parquet files, [yellow trip dictionary](https://www.nyc.gov/assets/tlc/downloads/pdf/data_dictionary_trip_records_yellow.pdf) and [zone lookup CSV](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zone_lookup.csv). TLC explicitly does **not** guarantee source data accuracy. Check your *actual allocation* and actual applicable reuse terms rather than assuming a licence name.
