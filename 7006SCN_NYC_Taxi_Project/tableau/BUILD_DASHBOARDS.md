# Build and publish four actual Tableau Public dashboards

**Do not reuse the supplied `7006SCN_NYC_Taxi_Dashboards.twb`: it has no worksheets or dashboards.** The old URL returned 404 when checked on 23 September 2026. Only complete this step AFTER Tasks 1–3 generated observed results from your allocated data.

1. Import `results/tbl_d1_quality.csv`. Create **Dashboard 1: Data quality & pipeline monitoring**: monthly clean rows, nonexclusive quality counts, raw-to-clean waterfall and measured Spark partitions. Label credit-card filtering as label observability, not solely an error. Display the year, source and measured bytes. Do not sum overlapping quality conditions as if mutually exclusive.
2. Import `results/tbl_d2_performance.csv`, `tbl_d2_confusion.csv`, `tbl_d2_curves.csv`, `tbl_d2_global_tree_importance.csv` and `tbl_d2_lime.csv`. Create **Dashboard 2: Model performance & feature importance**: all 4 models with PR-AUC/ROC-AUC, precision/recall/F1, confusion matrix (parameterised by model), binned ROC/PR polylines, **global** RF/GBT split importance by original feature and separate **local** LIME weights on one trip. Do not present split importance or LIME as causal effects. Include CV+refit seconds. The binned lines are plotting approximations; use the Spark evaluator numbers in the metrics table.
3. Import `results/tbl_d3_business.csv`, `tbl_d3_distance_DESCRIPTIVE_ONLY.csv`, `tbl_d3_borough_audit.csv`. Create **Dashboard 3: Business insights**: borough-hour tip patterns, retrospective distance bands, *observed label rates alongside predicted positive rates*, subgroup FPR and TPR. Suppress groups smaller than configured threshold; public workbook must contain no row-level trips. State that distance is not a pickup-time predictor and none of these comparisons establish causality.
4. Import `results/tbl_d4_scalability.csv`. Create **Dashboard 4: Scalability & cost analysis**: actual CV+refit times per model, measured groupBy query runtime across 10/25/50/100% training subsets (note each sampling action still scans Parquet), benchmark medians before/after shuffle setting, uncached vs cached repeats, separately measured cache-fill cost. Show dollar estimates ONLY if price/source were entered and configuration is comparable. Do not claim hardware scaling from a shuffle-count comparison alone.

**Design:** name/number four dashboards clearly, common restrained colours, show units and base rates, explain which performance split each number comes from, use descriptive alt text, constrain fonts/legends for readable 2x2 contact sheet. Publish the *workbook* to Tableau Public yourself. Open its URL in a signed-out browser and confirm all four dashboards resolve. Tableau Public is PUBLIC; importing even an extract can expose data, so only import suppressed, aggregated CSVs. Check that small cells are not recoverable via filtering/intersections.

Set `tableau.public_workbook_url` and `tableau.published_four_dashboards_verified=true` in your local `config/config.json` after you verified the live four-dashboard workbook. Export real dashboard screenshots to `results/tableau_dashboard_1.png`, `_2.png`, `_3.png`, `_4.png`. Rerun Task4. It checks the public URL and then combines your screenshots into `results/task4_dashboard_contact_sheet.png`. No dashboard images are invented by the code.

## A concrete layout to reproduce the earlier project's dashboard quality (without copying its accident data)

Create a **single** workbook named for the verified TR-04 source, with **four named dashboards** (not four separate `.twbx` files) using the CSV extracts generated after your own Task runs. Set each dashboard to approximately 1200×750 px; use navy `#17324D` for structure, teal `#168A85` for positive/rate measures, muted orange `#D67946` for negative/cost measures and accessible high-contrast annotation. Put source cohort, test period, denominator and units in a subtitle.

| Dashboard | Top row | Bottom row | Essential interpretation guardrail |
|---|---|---|---|
| **1. Data quality & pipeline** | KPI strip: actual raw rows, retained credit-card rows, actual compressed GiB and Spark partitions | Monthly record bars and a separate non-additive validity-flag bar chart | The flags overlap; cash-filtered rows are *unobserved tips*, not necessarily corrupt records. |
| **2. Model performance & feature importance** | Four-model aligned bars for PR-AUC vs cohort prevalence, ROC-AUC, precision/recall and CV+refit seconds | Confusion cells, ROC/PR line panels, global tree split importance AND distinctly labelled one-case LIME | Do not conflate global split counts, local LIME weights or causality. Same Nov–Dec holdout for all four models. |
| **3. Business insights** | Borough × pickup-hour high-tip **recorded** rate heatmap with cohort-n filter | Retrospective distance-band rates, borough observed-vs-predicted rates with FPR/TPR | A trip's final distance is not a pickup-time predictor; no dashboard supports a causal driver-repositioning promise. |
| **4. Scalability & cost** | Measured CV+full-refit times and 10/25/50/100%-row query-group timings | Shuffle-partition before/after, cache repeated-action before/after plus *cache-fill* cost, optional documented USD estimate | Sampling still scans Parquet, query scaling ≠ model-training scaling; cost estimates require your actual cluster tariff. |

Use a Month filter **only** on tables which include a month field; a Model filter only on per-model tables. Avoid relating unrelated CSVs on a missing key (that would multiply rows or silently change denominators). Keep different measure units in separate axes, format percentages explicitly, label all screenshots with the same Figure 1–4 numbers as your report, and inspect the public workbook while signed out. The repository stays **private**; only safe aggregated exports appear on Tableau Public. If the university cluster has no Tableau Desktop, use your own Tableau Public authoring environment; publication requires your account and cannot be completed by a Python script without that account and your genuine results.
